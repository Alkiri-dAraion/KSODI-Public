# KSODI Version Direction and Research Route

> A compact navigation route, not a delivery promise, implementation schedule
> or source of method formulas.

## Purpose

This file answers a limited question:

> Where does the current public KSODI line stand, and which later-version
> directions are presently visible without being predefined?

It does not duplicate the complete research programme. Use the linked sources
for defined method status, open questions, architecture and implementation
boundaries.

## Current public-main direction — v3.51

The moving Public `main` branch contains the reviewed v3.51 method line through
Layer 5:

```text
KSODI-Light
    |
K / S / O / D / I -> typed Z
                       |-- monadic IK
                       `-- relational R_0 gate -> dyadic IK_rel
```

The v3.51 work sharpens identities, profiles, typed statuses, reconstruction
routes, window semantics, provenance and the boundary between human-readable
views and machine-readable records. It does not claim universal validity,
production readiness or independent runtime conformance.

Public presence on `main` is not the same as a fixed tagged release. Consult
the root [README](./README.md), [START_HERE](./START_HERE.md) and citation
metadata for the current release and citation state.

## Next bounded route — v3.52

The currently visible v3.52 investigation route includes:

- Basic Visuals and more accessible reader views;
- preservation of drill-down routes from a view to operands, profiles,
  statuses and evidence;
- review of the post-Phase-H diagnostic record;
- initial support for more repeatable pre-release and release review; and
- possible layer-specific explanatory companions that retain a semantic
  minimum contract in the authoritative method files.

These are research and documentation directions. They are not a complete
scope, fixed priority order or dated commitment.

## Dependency-led later directions

Later work follows evidence and dependency gates rather than a fixed version
calendar:

```text
repeatable implementation evidence through typed Z
-> controlled records, uncertainty and accessible diagnostic views
-> scalable time, thread, group and population views
-> deeper longitudinal and relational research under separate contracts
```

These strands may overlap in practice, but a later view does not validate its
inputs. Independent runtime conformance, repeatability, declared contrast
tests and coverage remain necessary before implementation behavior can support
a method claim.

Additional R-family, observation, governance, security, learning or
action-adjacent questions require separately reviewed method, evidence,
sensitivity, publication and authority boundaries. Their exact version
allocation remains open unless another current Public source states a reviewed
decision.

This route intentionally does not disclose, predefine or validate the content
of later constructs.

## Dependency and authority guardrails

The route preserves these boundaries:

1. Open research is not method canon.
2. A version indication is not a delivery or implementation promise.
3. Implementation behavior is evidence, not automatic method authority.
4. KSODI-Light, a KSODI Observer and any future Controller are distinct roles;
   no mandatory `Light -> Observer -> Controller` pipeline is implied.
5. A future Controller requires separate policy authority, governance,
   oversight and evidence contracts.
6. Private work does not become Public without a selective review and
   explicit transfer decision.
7. Later R-family work must not be reconstructed from this navigation note.
