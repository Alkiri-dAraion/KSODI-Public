# Layer 4 — KSODI Relational Gate (`R_0` / `R0`)

> **Status:** public v3.50 reference release - strictly reviewed and released on 2026-08-26.

Status: authoritative reader-first Layer-4 set, strictly reviewed and released
2026-08-26.

`R_0` asks whether explicitly paired or grouped monadic trajectories satisfy
one declared availability and bounded-drift contract strongly enough for
relational comparison to be opened. It does not discover relation and does not
measure coupling, resonance, direction or meaning.

Active files:

- [`KSODI_Relational-Gate-R_0_V350.md`](./KSODI_Relational-Gate-R_0_V350.md) — authoritative method;
- [`KSODI_Relational-Gate-R_0_Implementation-Companion_V350.md`](./KSODI_Relational-Gate-R_0_Implementation-Companion_V350.md) — subordinate schemas, migration, pseudocode and tests.

Core boundary:

```text
complete comparable source-local Delta Z -> canonical R0
same fixed explicit M on every trajectory -> named R0^[M]

numeric R0 >= theta -> gate open
numeric R0 < theta  -> gate closed
non-numeric R0      -> gate not_evaluable
incomparable input  -> no valid R0 result
```

A numeric closed gate is still a valid observation. An open gate records
eligibility for a separately declared downstream relational evaluation; it is
neither permission nor action authority nor relational evidence by itself.

Reader sequence:

1. typed Z and source-local movement;
2. explicit `pi(j)` or constellation map;
3. R0 method;
4. implementation companion;
5. compatible downstream branches only after their exact open gate contract;
   current dyadic IK_rel requires explicit dyadic pairing and open numeric
   canonical complete dyadic R0 under the exact required profile.
