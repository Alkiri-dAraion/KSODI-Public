# Layer 4 — KSODI Relational Gate (`R_0` / `R0`)

## What this layer asks

`R_0` asks whether explicitly paired or grouped, distinguishable monadic
trajectories satisfy one declared availability and bounded-drift contract
required by a specified downstream relational branch.

An open gate establishes methodological eligibility only for that exact
compatible branch. It does not discover relation and does not measure
coupling, resonance, direction, agreement or meaning. It never authorizes an
action.

## Core contract

```text
complete comparable source-local Delta Z
  + explicit dyad/constellation and pairing map
  + fixed equal-coordinate normalized L1 reference profile
  -> canonical R0

same fixed explicit M on every trajectory
  -> named reduced R0^[M]

numeric R0 >= theta_R0_gate_open_min -> gate open
numeric R0 < theta_R0_gate_open_min  -> gate closed
non-numeric R0               -> gate not_evaluable
incomparable/invalid input    -> no valid R0 result

aggregate_drift_max = 1 - theta_R0_gate_open_min
```

L2 is a separate norm profile. Alternative coordinate weights are test
controls or later research, not hidden canonical parameters. Thresholds are
declared, versioned parameters whose origin and calibration status remain
visible; declaration does not prove empirical calibration.
`theta_R0_stable` is a v3.50 legacy alias only. Neither `open` nor a high R0
value asserts social, semantic, relational or systemic stability.

## Reader route

1. Start with complete typed Z and source-local `Delta Z` in Layer 2.
2. Verify the declared dyad or constellation and each source-local
   predecessor chain.
3. Read the v3.51 R₀ method and its exact profile/result identity.
4. Use the companion for conditional implementation—not as method authority.
5. Reproduce the reference fixtures.
6. Follow only an exact compatible open handoff to a selected downstream
   branch.

Current primary dyadic `IK_rel` additionally requires paired comparable
`Delta IK_w` under one shared exact canonical IK profile and an open numeric
canonical-complete dyadic R₀ under its exact required profile. Reduced or
n-adic R₀ does not open that branch.

## Machine, assistive and human views

The richest machine record retains operands, identities, profiles, raw value,
numeric policy, gate state, threshold provenance, statuses and reverse links.
An assistive LLM interpretation remains a separate attributable record. A
human display may round or simplify, but must retain drill-down and may not
replace the raw result or become action authority.

runtime-conformance claims, external implementation alignment, Controller
action, a GitHub tag, GitHub Release, DOI or Zenodo artifact.
