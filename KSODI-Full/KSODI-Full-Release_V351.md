# KSODI-Full v3.51 Release Surface

This document identifies the KSODI-Full material published on Public `main`
and selected for the complete v3.51 release. It is not itself a Git tag,
GitHub Release, DOI record or runtime-conformance claim.

## Scope

KSODI-Standard-Eval supplies the formal monadic line:

```text
K/S/O/D/I -> complete typed Z -> monadic IK views
```

After complete typed `Z`, the architecture branches. Layer 4 `R₀` evaluates
one declared relational-eligibility question from explicitly paired,
comparable source-local movements. It is not derived from monadic IK. Layer 5
`IK_rel` requires the exact compatible open numeric canonical-complete dyadic
R₀ handoff plus its own paired `IK_w` operands, component profile, identities
and typed status rules.

```text
complete typed Z trajectories
  +--> monadic IK views
  +--> R₀ eligibility
          +--> current primary dyadic IK_rel under its exact contract
```

An open R₀ gate is eligibility, not quality, relation proof, resonance,
agreement, success or action authority. `IK_rel` is projected relational
movement compatibility for its named components and profile; it is not a total
comparison of the complete trajectories.

## Later Full layers

`R_geom`, `R_pace`, signal-media and other R-family branches remain staged
research. Repository presence and historical formulas do not make them current
Public reference methods. Each later branch requires its own identity,
profile, mathematical reference suite and named cross-relation sensitivity
review before promotion.

## Observability and action boundary

KSODI-Full emits observations and diagnostics. It does not select targets,
authorize interventions or become a Controller because a result is numeric,
unusual, open or closed. Deterministic calculation, assistive interpretation,
governance policy, Controller decision, execution and resulting feedback
remain separately attributable stages.

Read the current
[Observability and Separate Controlled-Action Boundary v3.51](./KSODI_Observability-and-Controlled-Action-Boundary_V351.md).

## Compatibility and migration

The v3.50 method remains historically valid within its declared contracts.
v3.51 sharpens identities, profiles, statuses, provenance, relational
handoffs, epsilon calibration provenance, reconstruction routes and
reproducible test depth. Legacy material may be classified as:

- `v351_conformant`;
- `legacy_reconstructible`;
- `legacy_partially_reconstructible`;
- `legacy_noncomparable`; or
- `reconstruction_pending` where alternatives remain unresolved.

Non-conformance does not mean worthless or invalid. Missing provenance is not
reconstructed as fact, and implementations declare gaps instead of guessing.

## Release limits

This Public-main release surface does not claim:

- empirical calibration of thresholds or positive epsilon values;
- complete semantic interpretation or hidden-state access;
- production or independent runtime conformance;
- validation of later R-family formulas;
- Controller, steering or action authority; or
- that Public `main` already equals the tagged v3.51 Release or DOI snapshot.

Tag, GitHub Release, citation metadata, deposit and DOI remain separately
authorized closing actions.
