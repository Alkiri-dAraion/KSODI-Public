# Layer 1 — KSODI Operators

This folder contains all five current method and implementation-companion
packages; O additionally includes its Source-Need Gate. Each method remains
authoritative and carrier-neutral, while every implementation companion
remains conditional and subordinate. Public availability does not turn
optional views into mandatory calculations or make staged later research
operational.

Publication is layerwise. Operators K, S, O, D and I are now published here as
v3.51 reference methods and conditional companions; O additionally carries
its Source-Need Gate. Independent runtime conformance remains outstanding.
These packages are part of the full tagged v3.51 release. Independent runtime
conformance remains a separate evidence question.

## What this folder contains

Layer 1 observes one explicitly identified, source-attributed target event at a
time. Each applicable static operator produces one scalar coordinate:

```text
(K, S, O, D, I) =
(Context Completeness,
 Structural Coherence,
 Grounded Objectivity,
 Clarity,
 Information Impulse)
```

Each name denotes an observable operator dimension: Observable Context
Completeness, Observable Structural Coherence, Observable Grounded
Objectivity, Observable Clarity and Observable Information Impulse.

## The five questions in plain language

The operators are not five interchangeable quality scores. Each asks a
different question about one explicitly identified, source-attributed target
event under its own declared measurement basis:

| Operator | Plain-language observation question | Formal boundary |
| --- | --- | --- |
| `K` — Observable Context Completeness | Which relevant expected context requirements are observably fulfilled for this target event? | Uses a declared non-empty requirement set, admissible scope and availability relation; it is not general response quality. |
| `S` — Observable Structural Coherence | How well does the observable contribution satisfy the selected structural requirements and relations? | Uses a declared structural profile; structure is not meaning, truth or grounding. |
| `O` — Observable Grounded Objectivity | Where a source is required, how is the target event bound to a visible, admissible reference space? | The Source-Need Gate decides applicability; O is not universal truth or shared understanding. |
| `D` — Observable Clarity | How much local observable support and reconstruction-relevant distinguishability does the selected profile find? | Uses declared carrier, detector, segmentation and normalization profiles; D is not completed decoding or general semantic precision. |
| `I` — Observable Information Impulse | What observable information difference appears relative to the admitted reference baseline? | Uses a declared visible baseline and representation profile; I is not truth, intent or causal influence. |

These questions provide orientation. The linked versioned operator files define
the exact target, profile, applicability, calculation, result status and
non-claims. A low or high coordinate is not automatically good or bad, and the
five coordinates are not assumed to be statistically independent, complete or
equally useful in every domain.

```text
e_A(k_A)
  -> K_A(k_A), S_A(k_A), O_A(k_A), D_A(k_A), I_A(k_A)
  -> Z_A(k_A)
```

The five coordinates jointly form the monadic state vector `Z_A(k_A)`. A
single operator value is not itself a vector. Sequences, windows and Hangar
views may describe movement or distribution of one operator coordinate, but
they do not change the source identity or layer of the static value.

Entity `A` and Entity `B` remain distinguishable. Sender and receiver are
roles inside a declared exchange, not stable entity types. A downstream
relational evaluation becomes methodologically eligible only after an explicit
dyadic pairing or n-adic constellation map and the exact open numeric `R_0`
contract required by that branch. Every downstream construct must match the
admitted cardinality and profile.

## Shared measurement and result discipline

Operator results are bound to their declared observation object. A future
known-source residualization profile would first preserve and account for
known-source contributions in the admitted evidence and then evaluate the
explicitly identified residual object. It would not subtract K/S/O/D/I scores
after calculation. Raw and residual results remain distinct even when they use
the same operator family or happen to return equal values. This is a Future
Work guard, not a v3.51 profile or formula.

Each operator uses its own declared, versioned measurement basis:

| Operator | Required basis | Boundary |
| --- | --- | --- |
| `K` | non-empty expected context-requirement set, admissible scope and selected availability relation | stored or visible context is not automatically target- or receiver-accessible context |
| `S` | structural profile, segmenter, required relations, active components and weights | structure is not grounding, meaning or receiver understanding |
| `O` | Source-Need Gate and, where numeric O may open, a visible admissible non-empty reference space | required-but-unavailable support is not low O |
| `D` | carrier, segmentation, detector, local-support/dispersion and normalization profile | clarity is not grounding, context fit or Shannon capacity |
| `I` | visible admitted static information baseline and representation profile | retrieval is profile-dependent; a predecessor diagnostic is not canonical I or `Delta I` |

The common external Layer-1 result handed toward Z is:

```text
operator_result_status in {
  numeric,
  not_selected,
  not_observable,
  not_applicable
}
```

Every successful applicable finite calculation emits `numeric` with
`result_value in [0,1]`. Required basis or evidence that exists or is expected
but cannot be inspected maps to `not_observable`. Absence of a valid
operator-domain basis maps to `not_applicable`; elective omission maps to
`not_selected`. Invalid identity, profile, policy, configuration, attribution,
weights or calculation is a processing failure and produces no valid operator
result. None of these conditions may be encoded as numeric zero merely to fill
a coordinate.

This is the current Layer-1 output contract. The separately published
reader-first Layer-2 Z method and its conditional implementation companion
preserve this four-state result family beside the derived numeric-availability
mask. Their versioned method file remains authoritative for the Z construction.

## How to read measurement basis and operator distinction

A Layer-1 number is not self-explanatory. Its meaning depends on the declared
operator profile and on the concrete measurement-basis instance used for that
evaluation: the exact requirement set, structural relation set, admissible
reference space, detector input or information baseline. Equal numbers do not
establish equal target events, evidence, profiles or measurement bases. A
rounded display value is not a replacement for the raw result.

The five operators remain separate because they ask different observable
questions and use different bases. This semantic distinction is not proof that
the coordinates are mathematically orthogonal, statistically independent,
empirically non-redundant or complete for every communication question. Those
claims—including whether another coordinate is needed—remain open research.

Reader routes are therefore purpose-specific:

- use the five operator methods and the [v3.51 measurement-basis
  contract](./LAYER_1_MEASUREMENT_BASIS_AND_REFERENCE_DISCIPLINE_V351.md) to
  interpret or reproduce Layer-1 results;
- use the [bounded distinction research
  note](./LAYER_1_OPERATOR_DISTINCTION_WORKING_NOTE_V351.md) to inspect the
  open non-redundancy, orthogonality and completeness questions;
- use the [shared operator template](./OPERATOR_TEMPLATE_V351.md) only when
  authoring or reviewing an operator specification. It is a transparent
  developer/reviewer resource, not an additional method component and not
  required merely to apply the released operators.

## Reader path inside each operator

Each substantive operator file should let a new reader follow the same
reasoning dependency while preserving the operator's own semantics:

1. narrow observable question and plain-language orientation;
2. one bounded Human–Chatbot example and one bounded second-domain example;
3. canonical definition, evaluation unit, source and trajectory identity;
4. declared measurement basis, profile and applicability;
5. static components, calculation and interpretation;
6. comparability before source-local `Delta` and `Delta2`;
7. typed window and Hangar views;
8. explicit boundary to `R_0` and later relational layers;
9. compact formal summary and variable reference;
10. separation between the public method and implementation material.

This is a semantic reading order. It does not require identical formulas or
section numbering across the five operators.

## Coordinate order and two process topologies

The five operator coordinates can be evaluated independently. Their canonical
state-vector order is a stable reporting convention, not a causal calculation
chain:

```text
Z_A(k_A) =
  (K_A(k_A), S_A(k_A), O_A(k_A), D_A(k_A), I_A(k_A))
```

KSODI additionally uses two role-relative explanatory process topologies:

```text
sender-side formation:        K -> S -> O -> D -> I
receiver-side reconstruction: I -> D -> O -> S -> K
```

Sender-side formation describes how context-bound material may be structured,
grounded, transformed into a channel-appropriate form and emitted as an
observable information impulse.

Receiver-side reconstruction is a preferred iterative direction for an
unfamiliar signal: notice enough observable difference, establish
distinguishability, check available sources or reference spaces, examine
structure and place a reconstruction into context.

These topologies do not change entity identity, impose formula dependencies or
claim access to hidden human or machine processing. Established conventions
may abbreviate, reorder or parallelize practical reconstruction. Without a
shared convention, failed grounding may reopen segmentation, structural
analysis, source checking and contextual hypotheses.

Repeated events remain attributable. A repeated event may carry little new
static information relative to a declared baseline while its recurrence,
stagnation, burst or oscillation remains relevant in trajectory, window and
anomaly views. Static value and sequence pattern answer different questions.

## Three bounded examples

### Human and chatbot

A human `A` sends a request and a chatbot `B` answers. The contributions
remain in separate trajectories even when both are visible in one conversation.
On the next turn the roles may reverse without the entities changing identity.
A later relational comparison needs an explicit exchange and pairing rule.

### Unknown Morse-like signal

Repeated pulses may become detectable before their meaning is known. A receiver
may first observe informational movement and distinguish marks from gaps, then
test available references, inspect structure and attempt contextual
reconstruction. A shared convention accelerates decoding but is not required
to observe that a patterned carrier may exist.

Repetition may support an anomaly or contact-attempt hypothesis. It does not by
itself prove acknowledgement, meaning, intent, attack or causal coupling.

### Robots or embodied agents

Two robots may exchange well-formed signals while their spatial trajectories
diverge, or remain geometrically close while their response pace separates.
This motivates keeping staged `R_geom` and optional staged `R_pace` as
parallel later research branches after an open numeric canonical complete
`R_0` gate under the exact required profile and a cardinality-compatible
branch contract. Neither is a Layer-1 operator, motion controller or physical
safety system.

## Indices, comparability and optional views

Keep the following orders distinct:

- `n` — global event order;
- `k_A` / `k_B` — source-local trajectory positions;
- `j` — relational evaluation position;
- `pi(j) = (k_A(j), k_B(j))` — explicit pairing map.

A predecessor for operator-level `Delta` or `Delta2` comes from the same
declared trajectory under a comparable profile. Operator-level `Sigma`,
`Sigma(Hangar)`, drift and second-order drift are not automatically required
for every application. Select them by layer, use case and declared observation
question.

Storage schemas, detector configuration, pseudocode, model integration and
test fixtures are separate implementation material and must not redefine the
method.

## Layer boundary

Layer 1 ends with attributable operator observations. The complete monadic
KSODI-Standard-Eval line continues through `Z` and monadic `IK`. `R_0` is a
separate gate based on distinguishable `Z` trajectories plus an explicit
dyadic pairing or n-adic constellation rule. After an open numeric canonical
complete `R_0` gate under the exact required profile, cardinality-compatible
relational constructs may open. Current `IK_rel` is dyadic; an n-adic R0 gate
does not silently open it. `IK_rel`, staged `R_geom` and optional staged
`R_pace` remain parallel branch calculations with their own bases and profiles.

No Layer-1 operator, single repeated signal, visible shared context or
operator-specific diagnostic establishes relational coherence, resonance,
causality, desirability or authorization to intervene.
